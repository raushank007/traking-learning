# JVM Memory Layout & Interview Topics: Mind Map

## 1. Core Memory Areas 🧠
* **The Stack 🥞:** * **Nature:** Private to each thread.
    * **Contents:** Holds local primitive variables and method execution frames.
    * **Safety:** Inherently thread-safe (no locking required).
    * **Speed:** Extremely fast allocation/deallocation.
* **The Heap 🌍:** * **Nature:** Massive, shared memory pool for the entire JVM.
    * **Contents:** Holds all Java Objects (`new User()`, arrays).
    * **Challenge:** Because it is shared, concurrent access requires synchronization to prevent data corruption.

## 2. Thread Local Allocation Buffers (TLABs) 🎨
* **The Problem:** 50 threads allocating objects on the shared Heap simultaneously would cause a massive lock contention bottleneck.
* **The Solution (TLAB):** Each thread gets a small, exclusive chunk of memory inside the Heap's "Eden" space.
* **Benefit:** Threads can allocate normal-sized objects instantly within their TLAB without acquiring any locks.
* **TLAB Bypass:** Massive objects (e.g., `new byte[50_000_000]`) that don't fit in a TLAB skip it entirely and are allocated directly on the shared Heap (requiring slower, synchronized locking).

## 3. Generational Garbage Collection ♻️
* **Young Generation:**
    * **Eden Space 🪴:** Where new objects are born (inside TLABs).
    * **Minor GC:** Triggered when Eden fills up. Dead objects are cleared instantly.
    * **Survivor Spaces 🛡️:** Surviving objects from Eden are moved here.
* **Old Generation (Tenured) 🏛️:**
    * **Promotion:** Objects that survive multiple Minor GC cycles are promoted here. Designed for long-lived objects (e.g., Spring Beans).
    * **Major / Full GC:** Triggered when the Old Gen fills up.

## 4. Performance Red Flags 🚩
* **Stop-The-World (STW) Pauses:** During GC, the JVM halts application threads to safely move objects. A Full GC can pause a large heap for several seconds, causing the application to freeze.
* **`OutOfMemoryError`:** If a Full GC runs and the JVM *still* cannot free enough space for new objects, the application crashes.

## 5. Key Interview Questions 🎯
1. **"Why doesn't the JVM lock the entire Heap every time you call `new Object()`?"** -> *Answer: TLABs allow lock-free allocation for thread-specific chunks.*
2. **"What happens if you try to allocate a massive 100MB array?"** -> *Answer: It bypasses the TLAB and is allocated directly on the shared Heap with synchronization.*
3. **"What is the difference between a Minor GC and a Major GC?"** -> *Answer: Minor GC cleans the small Young generation (fast), Major GC cleans the massive Old generation (slow, causes noticeable STW pauses).*
4. **"Why is a Full GC considered a critical performance issue?"** -> *Answer: It triggers a Stop-The-World pause that completely freezes all application threads until the cleanup finishes.*
