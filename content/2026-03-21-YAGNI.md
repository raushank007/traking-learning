# YAGNI (You Aren't Gonna Need It) 🚫🔮

**Definition:** Always implement things when you actually need them, never when you just foresee that you need them.

**The Goal:** Prevent codebase bloat. Do not build features, interfaces, or generic abstractions based on assumptions about what the product manager *might* ask for next month.

## Java Example
*Requirement: Create a method to export an invoice to PDF.*

**❌ Bad ("Future-Proofing" too early)**
```java
// Wasting time building abstractions for formats no one asked for
public interface InvoiceExporter {
    void export(Invoice invoice);
}

public class PdfExporter implements InvoiceExporter { /* ... */ }
public class CsvExporter implements InvoiceExporter { /* ... */ } // Not requested!
public class XmlExporter implements InvoiceExporter { /* ... */ } // Not requested!
```

**✅ Good (Building exactly what is required today)**
```java
public class InvoicePdfExporter {
    public void exportToPdf(Invoice invoice) {
        System.out.println("Exporting to PDF...");
    }
}
```
