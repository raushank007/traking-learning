# KISS (Keep It Simple, Stupid) 🧠

**Definition:** Systems work best if they are kept simple rather than made complex. Simplicity should be a key goal in design, and unnecessary complexity should be avoided.

**The Goal:** Write readable, maintainable code. Avoid over-engineering a simple problem with heavy design patterns just to "show off."

## Java Example

**❌ Bad (Over-engineered for a simple 10% discount)**
```java
public interface DiscountStrategy {
    double apply(double amount);
}

public class TenPercentDiscount implements DiscountStrategy {
    public double apply(double amount) { return amount * 0.90; }
}

public class DiscountFactory {
    public static DiscountStrategy getStrategy(String type) {
        return new TenPercentDiscount(); 
    }
}
```

**✅ Good (Straightforward and readable)**
```java
public class Order {
    private double amount;

    public double applyStandardDiscount() {
        return this.amount * 0.90;
    }
}
```

**Interview Tip:** Always start with the simplest solution that works. Introduce design patterns (like Strategy or Factory) only when the complexity of the business rules forces you to.
