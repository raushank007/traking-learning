# 🚀 Spring Boot AOP: SDE 1 Foundation

Aspect-Oriented Programming (AOP) allows us to separate cross-cutting concerns (like logging, security, and transactions) from our core business logic.

## 🍽️ The Restaurant Analogy

To understand AOP, imagine a high-end restaurant:
* **🧑‍🍳 The Chef (Core Service):** Focuses only on cooking (business logic).
* **🤵 The Host/Manager (Aspects):** Handles tasks like greeting guests, checking IDs, or managing refunds (cross-cutting concerns).
* **🎭 The Proxy:** Spring wraps the Chef in a Proxy. The Proxy intercepts requests, triggers the Host/Manager, and then passes the request to the Chef.

## 📚 Core Terminology

* **📝 Advice:** *What* the action is (e.g., logging a message).
* **🎯 Pointcut:** *Where* the action happens (e.g., "execution of `UserService.saveUser`").
* **⚙️ Aspect:** The class that combines the Pointcut and the Advice.

## 💻 Code Implementation (Java)

### 1. The Core Service (The Chef)
The business logic remains clean and unaware of any AOP magic.

```java
@Service
public class UserService {
    public void saveUser(String name) {
        System.out.println("Chef: Cooking up a new user account for " + name);
    }
}
```

### 2. @Before Advice (The Host)
Executes *before* the target method runs.

```java
@Aspect
@Component
public class LoggingAspect {
    @Before("execution(* com.example.UserService.saveUser(..))")
    public void logBeforeArrival() {
        System.out.println("Host: Guest is arriving! Logging time...");
    }
}
```

### 3. @AfterThrowing Advice (The Manager)
Executes only if the target method throws an exception.

```java
@Aspect
@Component
public class ErrorHandlingAspect {
    @AfterThrowing(
        pointcut = "execution(* com.example.UserService.saveUser(..))", 
        throwing = "ex"
    )
    public void handleBurnedFood(Exception ex) {
        System.out.println("Manager: Apologizing to the guest! Error: " + ex.getMessage());
    }
}
```

### 4. @Around Advice (The Maître D')
Takes full control of the execution. It can modify inputs, control when the method runs, and modify outputs. It requires the `ProceedingJoinPoint` to trigger the target method.

```java
@Aspect
@Component
public class SecurityAspect {
    @Around("execution(* com.example.UserService.saveUser(..))")
    public Object manageEntireProcess(ProceedingJoinPoint joinPoint) throws Throwable {
        
        // 1. Intercept and inspect arguments using getArgs()
        Object[] args = joinPoint.getArgs();
        if (args.length > 0 && args[0] instanceof String) {
            String guestName = (String) args[0];
            if (guestName.equals("Plankton")) {
                throw new RuntimeException("Maître D': You are banned!");
            }
        }
        
        System.out.println("Maître D': Preparing the kitchen.");
        
        // 2. Proceed with the execution (let the Chef cook)
        Object result = joinPoint.proceed(args); 
        
        System.out.println("Maître D': The meal is done.");
        
        // 3. Return the result
        return result; 
    }
}
```


## 🏗️ SDE 2 Architecture: Custom Annotations & Proxy Pitfalls

### 1. Custom Annotations
Relying on string-based pointcuts (`execution(* com.example...*)`) is fragile. The enterprise solution is creating custom annotations to explicitly tag target methods.

**The Annotation:**
```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface TrackTime {}
```

**The Aspect:**
```java
@Aspect
@Component
public class PerformanceAspect {
    
    // Target the annotation directly
    @Around("@annotation(TrackTime)")
    public Object measureTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        
        Object result = joinPoint.proceed(); 
        
        System.out.println("⏱️ Method took " + (System.currentTimeMillis() - start) + "ms");
        return result;
    }
}
```

### 2. The Self-Invocation Problem
Spring AOP proxies wrap the outside of a Bean. If `saveUser()` calls `validateData()` *inside the same class*, the call happens entirely inside the kitchen. The Proxy at the front door is bypassed, and the AOP logic will not execute.

**The Solutions:**
1.  **The Architect's Fix (Best Practice):** Move `validateData()` into a completely separate Spring Bean (e.g., `ValidationService`). Calling an external Bean forces the request to go through that Bean's Proxy.
2.  **The Expose-Proxy Fix (Workaround):** Force the class to call its own proxy instead of itself:
    `((UserService) AopContext.currentProxy()).validateData();`

## 🏛️ SDE 3 System Design: Weaving & Enterprise Patterns

### 1. Spring AOP vs. AspectJ
Spring AOP relies on **Runtime Proxies**. Full AspectJ does not use proxies; it uses **Weaving** to physically modify the Java bytecode.

| Feature | Spring AOP (Proxies) | AspectJ (Weaving) |
| :--- | :--- | :--- |
| **Setup** | Easy (Standard Spring setup) | Complex (Requires `ajc` compiler plugins) |
| **Performance** | Slight runtime overhead | Native execution speed ⚡ |
| **Target Methods** | Only `public` Spring Beans | `private`, `static`, or any Java object |
| **Capabilities** | Method execution only | Field access, object creation (`new`), etc. |

### 2. Types of Weaving (AspectJ)
When using AspectJ, you must decide *when* the bytecode gets modified:
* **Compile-Time Weaving (CTW):** The AspectJ compiler (`ajc`) injects the Advice into the `.class` files during the build process. Requires source code access.
* **Load-Time Weaving (LTW):** A Java Agent intercepts `.class` files and modifies their bytecode dynamically exactly as the ClassLoader pulls them into the JVM. Great for third-party libraries, but increases application startup time.

### 3. @Slf4j vs. AOP Logging
* **`@Slf4j` (Manual):** A Lombok shortcut that creates a `Logger` object. You still have to manually write `log.info()` inside your core business logic, cluttering the Chef's kitchen.
* **AOP Logging (Automated):** Keeps the business logic 100% clean. The Aspect intercepts the call and handles the logging entirely from the outside.

### 4. When to Use Aspects
Aspects should strictly be used for **Cross-Cutting Concerns**. Never put core business logic (like calculating taxes) inside an Aspect.

Top 5 Use Cases:
1.  🔐 Security & Authorization
2.  🗄️ Transaction Management (e.g., `@Transactional`)
3.  ⏱️ Performance Monitoring
4.  📝 Auditing
5.  🧠 Caching

### 5. Aspect Ordering
When multiple Aspects target the exact same method (e.g., a Security check and a Logging tracker), you must define the order of the Proxy chain to prevent logic errors.

We control this using Spring's `@Order` annotation on the Aspect classes. Lower numbers have higher precedence (they run first on the way in).

```java
@Aspect
@Component
@Order(1) // Runs FIRST. Blocks the request before logging if token is invalid.
public class SecurityAspect { ... }

@Aspect
@Component
@Order(2) // Runs SECOND. 
public class LoggingAspect { ... }
```
