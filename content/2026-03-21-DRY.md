# DRY (Don't Repeat Yourself) 🔄

**Definition:** "Every piece of knowledge must have a single, unambiguous, authoritative representation within a system."

**The Goal:** Reduce code duplication so that a change in business logic only requires updating the code in one place.

## Code Smells (WET - Write Everything Twice)
* Copy-pasting the same validation logic across multiple methods.
* Hardcoding "magic numbers" (like a 0.10 tax rate) or "magic strings" (like "PENDING") in multiple files.

## Java Example

**❌ Bad (Duplicated Logic)**
```java
public void processRetail(Order order) {
    if (order.getStatus().equals("PENDING") && order.getAmount() > 0) {
        order.setStatus("PROCESSED");
    }
}

public void processWholesale(Order order) {
    if (order.getStatus().equals("PENDING") && order.getAmount() > 0) {
        order.setStatus("PROCESSED");
    }
}
```

**✅ Good (Single Source of Truth)**
```java
private boolean isProcessable(Order order) {
    return order.getStatus() == OrderStatus.PENDING && order.getAmount() > 0;
}

public void processRetail(Order order) {
    if (isProcessable(order)) markAsProcessed(order);
}

public void processWholesale(Order order) {
    if (isProcessable(order)) markAsProcessed(order);
}
```

**Interview Tip:** Beware of the "Wrong Abstraction." Only abstract code if it truly represents the same business domain. If two unrelated pieces of code just happen to look similar today, leave them separate. Duplication is cheaper than the wrong abstraction.
